# JAKA Mini 2 六关节 1:1 相对跟随设计

## 目标

在已验证的 J1 相对跟随基础上，将控制扩展为两台 JAKA Mini 2 的六关节相对 1:1 跟随：操作臂 `192.168.0.101` 由人工拖拽，跟随臂 `192.168.0.102` 执行对应的六关节目标。该阶段只验证机械臂本体，不控制灵心巧手，不接入视觉或 OpenPI 推理。

## 控制接口

- 操作系统：Ubuntu 22.04。
- 控制库：JAKA 官方 C++ SDK，动态库 `libjakaAPI.so`。
- 指令接口：`servo_j(&command, MoveMode::ABS, 1)`。
- 伺服周期语义：`step_num=1`，对应 SDK 文档所述的 8 ms 插补周期。
- 不使用 ROS/ROS 2，不使用自行实现的原始 TCP 协议。

## 角色与数据流

- 操作臂：`192.168.0.101`。
- 跟随臂：`192.168.0.102`。
- 操作臂发布进程以约 125 Hz 读取六个实际关节角，并通过本机 Unix datagram socket 发送数据。
- 跟随进程持有 `.102` 的唯一 SDK 会话，接收最新操作臂数据并发送六关节绝对目标。

## 相对映射

进入有效拖拽状态后，程序同时保存：

- `operator_zero[0..5]`：操作臂当时的六关节角度；
- `follower_zero[0..5]`：跟随臂启动时的六关节实际角度。

每个关节采用相同的相对 1:1 映射：

```text
follower_target[i] = follower_zero[i]
                   + operator_current[i]
                   - operator_zero[i]
```

其中 `i=0..5` 分别对应 J1–J6。所有角度在程序内部使用弧度。映射比例为 `1.0`，符号为 `+1`。

本测试不添加人为的总位移限幅或比例缩放。机器人控制器自身的关节软限位、速度限制、急停和安全设置必须保持有效。操作人员负责在现场控制拖拽速度和范围。

## 启动条件

程序不执行机器人上电或机器人使能。启动运动前必须满足：

- `.102` 已由现场人员上电并使能；
- `.101` 已上电、使能并处于拖拽模式；
- 用户显式提供启动令牌 `START_SIX_JOINTS`；
- 两台机械臂工作空间清空，人员可立即操作急停。

只有收到第一帧满足操作臂就绪条件的数据后，跟随程序才捕获零位并调用 `servo_move_enable(TRUE)`。

## 停止与故障处理

出现下列任一情况时停止发送新目标：

- 操作臂状态不再满足上电、使能、拖拽；
- 操作臂数据超过 100 ms 未更新；
- 操作臂报文非法或 SDK 读取失败；
- 跟随臂实际关节读取失败；
- `servo_move_enable` 或 `servo_j` 返回错误；
- 达到用户设置的运行时间；
- 用户发送 `SIGINT` 或 `SIGTERM`。

停止清理顺序为：

1. 停止发送 `servo_j`；
2. 如果已进入伺服模式，调用 `motion_abort()`；
3. 调用 `servo_move_enable(FALSE)`；
4. 登出跟随臂 SDK；
5. 启动脚本终止操作臂发布进程并清理 Unix socket。

## 记录与统计

跟随进程以降低频率读取跟随臂实际关节角，避免每个伺服周期的状态查询阻塞指令发送。日志周期性输出：

- 操作臂 J1–J6 当前角度；
- 跟随臂 J1–J6 目标角度；
- 跟随臂 J1–J6 实际角度；
- J1–J6 当前绝对误差（度）；
- 当前报文通信延迟（毫秒）。

结束摘要输出：

- `stop_reason`；
- `active_duration_sec`；
- 指令数量与实际状态采样数；
- 平均和最大通信延迟；
- J1–J6 各自的平均与最大绝对误差；
- `motion_abort`、关闭伺服和 SDK 登出的返回码。

通信延迟仅指操作臂数据报从发布到接收的单机进程间延迟，不等同于机械臂的机械响应时间。目标角与实际角误差包含跟随臂动力学响应滞后。

## 文件与启动方式

新增文件：

- `six_joint_follow_test.cpp`：六轴跟随程序；
- `run_six_joint_follow_test.sh`：由现场人员运行的启动脚本；
- `test_six_joint_follow.py`：安全契约与启动顺序测试。

计划启动接口：

```bash
./run_six_joint_follow_test.sh START_SIX_JOINTS 20
```

第一次实机测试由用户现场运行，助手只负责准备、编译和静态验证，不远程启动运动。

## 验收标准

- 程序能够正常连接 `.101` 与 `.102`，并进入六关节伺服模式；
- 六关节目标均满足相对 1:1 公式；
- 日志中不存在关节交叉映射；
- 正常计时结束时 `stop_reason=DURATION`；
- 两个进程正常退出，操作臂发布端无持续 `send_errors`；
- 平均通信延迟保持在当前 J1 基线的同一量级；
- 六关节静止后误差可收敛，运动过程误差单独作为后续性能优化依据。
